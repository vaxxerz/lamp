## 3. 디자인 시스템

- 콘셉트 "Illuminate the Invisible": 어두운 장면(NIGHT)은 보이지 않는 문제, 밝은 장면(PAPER/WHITE)은 드러난 증거를 맡는다. 05 → 06이 어둠에서 빛으로 넘어가는 전환점이다.
- 색: `#09090b` 근흑 / `#f5f5f3` 오프화이트 / 인디고 `#4f46e5`(다크에선 `#818cf8`). 작성자 색은 제품 형광펜 토큰(노랑·초록·파랑·분홍)을 그대로 쓴다.
- 글자: Pretendard Variable. 히어로 148~200, 제목 72~92, 보조 30~40, 주석 20~24px(1920×1080 기준).
- 그리드: 좌우 여백 128px. 제목은 항상 위쪽 112px에서 시작한다.
- 모션: 단계 공개(페이드+18px 상승), 05의 빛 확산, 09의 제안→수락 변화, 12의 파이프라인 점등, 14의 데이터 흐름 점선만 쓴다.

## 5. 슬라이드별 발표자 노트

전체 노트는 HTML 각 장의 `data-notes`에 있다(`N` 키로 표시). 요약:

1. 팀플이 끝났습니다. 조원 평가는 어떻게 이루어질까요? (잠깐 멈춤)
2. 근거는 동료평가지 한 장. 모두 5점. → "이 중 누가 실제로 일했을까요?"
3. 알바몬 940명 조사에서 37.4%가 무임승차를 꼴불견 1위로 꼽았고, 2013년 조사에서도 1위였다.
4. 친분 편향, 소규모 팀 평균의 한계, 학기 말 한 번 — 필요한 건 과정의 기록.
5. 과정의 기록은 이미 있다. 비추지 않았을 뿐. (주제 연결)
6. 주제: 등잔 밑이 어둡다 — 평가는 멀리(결과물·평가지)를 비추고, 증거는 가까이(문서·회의·할 일)에 있다.
7. Lamp.: 기여를 새로 입력하지 않고 이미 한 일을 증거로. 실제 배포 화면.
8. 팀 연결 → 작업 → 기여 확인 → AI 분석 → 교수 확인 → 라이브 시연.
9. 동시 편집은 하나의 버전으로 합쳐져 작성자가 사라진다.
10. 제안 모드 → 입력 끝 감지 → docx 변경 추적으로 작성자 식별(API가 제안 작성자를 주지 않아 필요한 우회) → 기록 후 자동 수락 → 확정 기여. 동명이인·미반영 제안은 보류.
11. 확정/단독/추정/참고. 추정·미확인은 확인된 활동 수에 넣지 않는다.
12. 직접 1,000자 10점, 붙여넣기 3점, 할 일(확인) 3점, 출석 1점. ln으로 10배 → 약 1.7배. 과목 가중치 → 팀 내 비중.
13. 규칙 엔진이 먼저 계산하고, LLM은 문장만 쓰고, 근거 검사에서 걸리면 규칙 결과로 되돌린다. AI는 판사가 아니라 서기.
14. 실제 생성된 리포트: 패턴, 근거 건수, (추정) 표기, 다음에 해볼 일. 입력은 데모용 시드 데이터.
15. RLS, DB 트리거·함수로 점수 계산, drive.file, AES-256-GCM, 별도 워커, AI 실패 시 규칙 리포트.
16. 시스템 아키텍처 상세(아티팩트 도면): Vercel·Supabase·외부 API·CI/CD·제안 수락 워커. 심사 자료용.
17. 과목 생성 → 팀 참여 → 자동 기록 → 중간 점검 → 근거 확인. 독립 팀은 지금 동작, 파일럿·LMS는 계획.
18. 판단은 교수가. 근거는 Lamp.가. 감사합니다.

예상 질문(본문에서 뺀 내용):
- 감시 아닌가? → 점수는 참고 지표이고 최종 판단은 교수. 학생도 같은 데이터를 본다.
- 글자 수를 부풀리면? → ln 수확체감, 건당 상한 30점, 붙여넣기 0.3배, 할 일은 팀원 확인 시 만점.
- 기록되지 않는 기여는? → AI가 단정하지 않고, 교수용 리포트에 면담 질문을 붙인다.
- 왜 새 도구인가? → 옮기지 않는다. 쓰던 구글 문서를 연결만 한다.

## 6. 구현 여부를 확인하지 못했거나 조건이 붙는 주장

| 주장 | 상태 | 비고 |
|---|---|---|
| 제안 모드 자동 수락이 배포 환경에서 상시 동작 | 조건부 | 워커(`npm run worker`)는 Vercel 밖에서 따로 실행해야 한다. 발표 당일 노트북에서 켜야 함 |
| 워커 주기·안정 판정 시간 | 환경변수 | 코드 기본값은 1초/1초(`WORKER_INTERVAL_MS`, `SUGGESTION_STABLE_MS`). 발표에선 초 단위 수치를 쓰지 않음 |
| 동료평가 입력 화면 | 확인 못함 | DB 산식(불일치 ≥15%p)과 보고서 표시(`Reports.tsx`)는 있으나 학생 입력 UI는 찾지 못함. 발표 본문에서 뺌 |
| 팀원 인정(👍) ×1.2 | DB 구현 | `get_team_contributions`에 있음. 화면에서 실제로 누르는 흐름은 이번에 직접 확인하지 않음 |
| Realtime 갱신 | 미커밋 | `20261108000016_workspace_realtime.sql`이 아직 커밋되지 않은 작업 트리에 있음 |
| AI 모델 | 환경 의존 | OpenRouter 경유 `anthropic/claude-sonnet-5.5`가 기본값이고 `OPENROUTER_MODEL`로 바뀔 수 있음 |
| Drive Activity 스코프 | 심사 필요 가능 | `drive.activity.readonly`는 실서비스 게시 시 구글 심사가 필요할 수 있음(docs/GOOGLE.md) |
| 학과 파일럿 · LMS · GitHub 연동 | 계획 | 15장에 "계획"으로 표기 |
| 무임승차 설문 수치 | 외부 자료 | 2007·2013년 알바몬 웹 설문 보도. 최신 국내 통계는 찾지 못함 |

데모 데이터 주의: 데모 팀의 실제 기록은 학생1 한 명의 테스트 입력뿐이다(무의미한 문자열 포함). 그래서 문서 원문이 보이는 화면(AI 보고서의 활동 목록 등)은 쓰지 않았다. 발표 전에 시드 데이터를 정리하면 07·13 화면과 라이브 시연이 훨씬 설득력 있어진다.
